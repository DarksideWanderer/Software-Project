# Sprint 3 - 家电检索、绑定与缓存体系

**时间范围**：第 3 个迭代周期（1 周）
**Sprint Goal**：将系统从“预置设备展示”推进到“用户主动发现、绑定、缓存和管理设备”的真实家庭流程，并扩展 C++ 设备模拟器支持更多设备类型和自定义编号。

## 1. 背景与范围

本 Sprint 引入 `discover -> bind -> cache -> manage` 流程。C++ 设备连接 DeviceHub 后先成为候选设备，用户在前端“添加家电”弹窗中选择绑定，绑定结果写入 `backend-core/data/home_state.json`。刷新后，已绑定设备、显示名、房间、状态和用户场景需要恢复。

## 7. 依赖关系

- 候选列表依赖 DeviceHub `_registry`。
- 控制依赖缓存中的 `type` 与当前注册类型一致。
- 前端场景和 NLU 依赖设备 `name`、`room` 可编辑。
- `home_state.json` 是轻量持久化，不等同正式数据库。

## 8. Acceptance Criteria

- 未绑定设备时首页不显示默认家电。
- 已启动但未绑定的模拟器只出现在添加家电弹窗。
- 已绑定设备刷新后仍存在，并保留名称、房间和缓存状态。
- 已绑定设备不重复出现在候选列表。
- 断开模拟器后设备显示离线且不可控制，但仍可编辑或移除。
- 同 ID 异类型注册时显示冲突，命令和相关场景被拦截。

## 9. Definition of Done

- `backend-core/data/home_state.json` 被 `.gitignore` 忽略。
- 候选来自后端发现 API，不写死在前端。
- 添加设备流程在弹窗内完成。
- 设备断连后后端不把缓存误判为在线。

## 10. 测试与验收方案

- 初始访问 `/api/v1/devices` 应为空或仅有缓存绑定设备。
- 启动 `simulator --device ac --id ac-003` 后，`/devices/discover` 返回候选。
- 绑定后刷新页面，设备仍在家庭列表中。
- 再次 discover 时已绑定设备不出现。
- 关闭模拟器后设备显示离线。
- 启动同 ID 不同类型设备时返回 `conflict: true`。

## 11. Sprint Review 预期成果

- 演示空家庭到检索、绑定、控制、刷新恢复。
- 演示 `ac-003`、`ac-004` 两台空调分别命名到不同房间。
- 演示离线和冲突安全处理。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 只缓存状态不校验在线 | 进程死亡仍可控制 | `online` 以 DeviceHub 连接为准。 |
| 同 ID 异类型误操作 | 场景或 AI 操作错误设备 | 标记冲突并拒绝命令。 |
| 新设备类型控件不全 | 前端无法完整控制 | 先支持通用开关和常见数值控件。 |

## 13. Sprint Retrospective

本 Sprint 让系统从 Demo 设备列表进入真实发现和绑定模式。主要技术债是持久化仍为 JSON 文件，缺少多用户隔离和数据库迁移。
