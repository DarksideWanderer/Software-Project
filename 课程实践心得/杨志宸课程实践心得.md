## 课程实践心得

在本学期的软件工程课程项目中，我负责 AI 服务层中 **TTS（语音合成）模块** 的独立开发。通过这一实践，我对软件工程的全生命周期有了深刻体会。

**一、架构设计方面**，我实现了"**云端优先、本地兜底**"的双引擎降级策略：优先调用阿里云百炼 DashScope Qwen-TTS 进行高质量语音合成，当网络异常或 API Key 缺失时自动降级为本地 pyttsx3 引擎。这一设计在保证用户体验的同时，也提升了系统的鲁棒性。

**二、工程规范方面**，我严格遵循项目约定的 RESTful 接口规范（如 `/internal/v1/tts/speech` 路径设计）、PEP 8 代码风格、以及 Conventional Commits 提交规范。同时，我设计了 **音频文件生命周期管理** 机制（30 分钟过期 + 后台定时清理），避免了磁盘空间的无限增长。

**三、质量保障方面**，我为 TTS 模块编写了 **11 个单元测试**，覆盖云端合成成功、自定义音色、API Key 缺失降级、API 异常降级、云端返回无音频 URL、本地引擎崩溃兜底、以及过期音频清理等全部核心场景，测试覆盖率达 **100%**。

**四、团队协作方面**，我撰写了详细的模块 README 和技术方案文档，并通过 FastAPI 的旧版路径兼容机制（[/ai/tts/synthesize](vscode-file://vscode-app/d:/Software/Microsoft VS Code/fc3def6774/resources/app/out/vs/code/electron-browser/workbench/workbench.html)），确保了与项目中其他模块及历史调用的无缝衔接。

通过这次实践，我深刻认识到：一个可靠的软件系统不仅需要功能完备，更需要考虑 **异常降级、资源管理、向后兼容和可测试性** 等工程化要素。
